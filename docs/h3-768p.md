# MiniMax H3 — 768p mode and the Flex recipe

Resolution options for H3 workflows: **480p**, **ESRGAN 2x** (stored value `720p`, unchanged) and
**768p** (new, native two-stage). 768p costs **2x credits** and is an advanced-features option like 720p.

## What 768p does
`src/lib/h3TwoStage.ts` rewrites the finished single-stage H3 graph into the validated two-stage layout:
low-res (half the edges, e.g. 672x384) over the first part of the sigma schedule -> `MiniMaxH3LatentUpscaleWithModel`
on stage 1's `denoised_output` -> high-res (1344x768) over the rest, with fresh noise at the switch sigma.

| Family | Template sigma source | Split |
|---|---|---|
| Official H3 (Flex) | `ManualSigmas` 6 steps, lcm | 3 + 3 |
| Singularity / Dasiwa hybrids (turbo) | `BasicScheduler` 8 steps, euler | 6 + 2 (`SplitSigmas`) |

Each stage gets its own sigma-shift / sage-patch chain (as in the validated graphs). Duration is capped at
`MAX_DURATION_768P_SECONDS` (10s) in the kickoff route and the review UI; 15s is only validated on the L40S.

## Flex templates (official H3 only)
`data/minimax_ref2v_flex.json.tmpl` (ref2va pruned) and `data/minimax_h3_flex.json.tmpl` (fl2va pruned): a LoRA node
wired in the template, `ManualSigmas` (6 steps), `lcm`, no `MiniMaxH3SigmaShift`, no `BasicScheduler`.
The Flex recipe is LoRA + sigmas + sampler together (the LoRA is only valid with that schedule), which is why these are
separate templates instead of a LoRA swap on the turbo templates.

**The LoRA itself is the workflow's required LoRA** (admin preset with `isConfigurable=false`, same mechanism as the
turbo speed-up LoRA): the builders write it into the template's LoRA node (name + strength). The template value
(`pika_h3_flex_ref2va_v1_bf16` / `pika_h3_flex_fl2va_v1_bf16`) is only the default when no required LoRA is
configured. No second LoRA node is ever injected, so turbo cannot be stacked on Flex. If a Flex row is left with
the old turbo preset as its required LoRA the builder logs a warning and uses it — set the Flex preset as the
required LoRA when switching the row.
(`/data` is git-ignored; the tracked templates are force-added.)

## Worker requirements
- ComfyUI with `MiniMaxH3LatentUpscaleWithModel` (PR #17412), `comfy-kitchen >= 0.2.40`, and
  `models/latent_upscale_models/minimax_h3_latent_upscaler_3d_fp16_V2.safetensors`.
- Sage attention workers get one `MiniMaxH3MemoryEfficientSageAttentionPatch` per stage (existing `useSageAttention`
  mechanism). **Without the patch on a sage worker long clips turn to noise** — never skip it there.
- Local workers: declare `h3_latent_upscale` in `x-worker-capabilities`, or (undeclared workers, e.g. the L40S)
  set `ENABLE_H3_TWO_STAGE_LOCAL=true` on the site. Default is off: workers without it are never handed a 768p job
  (`claimLocalJob(userId, { allowH3TwoStage })`). RunPod serverless needs image >= GmComfy `51bbae4`.

## Enabling it (DB, nothing runs automatically) — workflow rows
Capabilities are opt-in per workflow row (kickoff rejects a resolution not in `capabilities.resolutions`).

```sql
-- Hybrids: keep their LoRA/steps, add 768p and the x2 rule
UPDATE workflows
SET capabilities = capabilities || '{"resolutions":["480p","720p","768p"]}'::jsonb,
    quota_cost_rules = '[{"id":"res-768p","label":"768p x2","multiplier":2,"when":{"exactResolution":"768p"}}]'::jsonb
WHERE id IN ('singularity-h3','singularity-h3-fl2v','singularity-h3-r2v','dasiwa-h3','dasiwa-h3-fl2v','dasiwa-h3-r2v');

-- Official H3: switch to Flex in place (same workflow ids), 6 fixed steps, 3 resolution options
UPDATE workflows SET "templatePath" = 'data/minimax_ref2v_flex.json.tmpl' WHERE id = 'minimax-h3-r2v';
UPDATE workflows SET "templatePath" = 'data/minimax_h3_flex.json.tmpl'    WHERE id IN ('minimax-h3','minimax-h3-fl2v');
UPDATE workflows
SET capabilities = '{"steps":[6],"freeSteps":6,"resolutions":["480p","720p","768p"]}'::jsonb,
    quota_cost_rules = '[{"id":"res-768p","label":"768p x2","multiplier":2,"when":{"exactResolution":"768p"}}]'::jsonb
WHERE id IN ('minimax-h3','minimax-h3-fl2v','minimax-h3-r2v');
-- also (admin UI): add the Flex LoRA presets (isConfigurable=false) pika_h3_flex_ref2va_v1_bf16.safetensors /
--   pika_h3_flex_fl2va_v1_bf16.safetensors and, on these three rows, replace the turbo ids in compatible_lora_ids with them
```
Rollback: point `"templatePath"` back at the old template (`data/minimax_h3.json.tmpl`,
`data/minimax_ref2v_template.json.tmpl`) and restore `capabilities` / `quota_cost_rules`.

  Dasiwa 6+2 158s (480p 122s); Singularity 6+2 124s (480p 95s); two-person swap r2v with 2 refs + ref video + audio 200s.
